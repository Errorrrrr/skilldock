# 来源与更新规则

| 来源 | 内容获取 | 更新与分发 |
| --- | --- | --- |
| 远程 Git | 受管缓存固定提交，保留完整共享结构 | 手动检查或定时更新；仅所选成员入库，整包订阅允许新增成员 |
| 网站安装 | 已支持站点适配器解析的仓库或版本下载源 | 具备来源标识时支持远程更新；仅保存网站名称、网址不会创建更新任务 |
| 本地文件夹 | 手动扫描并确认同步原目录 | 不推断 Git remote、不定时更新；确认同步后按预设纳新、排除和跟随规则分发 |
| 工具目录归集 | 归集与备份 | 不作为更新来源 |
| 旧本地引用 | 直接使用原实体 | 原目录内容自然变化，不生成更新任务 |

## 模块边界

- 更新中心、Skill 列表更新标记、侧栏数量、状态栏检查和任务统计使用相同远程更新条件。
- 本地文件夹通过预设中的文件夹扫描流程确认同步；更新中心提供入口提示，不再展示为定时任务。
- 后端拒绝为本地来源开启 notify/auto；CLI 的显式本地检查/同步仍可手动调用，调度器始终排除本地来源。
- GitHub 与 GitLab（含自建、子群组）支持仓库子目录网页链接；带斜线分支可显式填写分支。
- Git 单成员、部分成员与集合共用快照模型。未选成员不入库；整包订阅可纳新，已排除路径保留；固定目标、未应用预设的目标不跟随。
- 删除、改名保留原安装并待审阅；同名分发冲突不覆盖外部文件。
- 移除更新管理保留来源追溯和所有实体、预设、分发关系；后台与手动远程更新一并停止。

## 每天固定时间

- 更新中心「来源与计划 → 设置时间」支持按间隔或每天固定时间（HH:mm）；策略仍可选关闭、仅检查提醒、自动更新入库。
- 每天时间按本机时区计算，保存后显示下次检查时间。检查成功、失败或手动检查后，均重新计算下次计划；关闭策略清空下次检查时间。
- 桌面调度器每 60 秒检查到期来源；完全退出时停止，重新启动后补检查到期计划，不逐天补跑。夏令时跳过的时刻顺延到首个有效分钟，重复时刻只采用第一次。
- 旧配置未设置 `dailyTime` 时继续按 `intervalHours` 执行。切回间隔模式清除 `dailyTime`。

## 旧数据兼容

读取旧状态时，将关联本地包、原先由 .git 推断成 Git 的来源还原为 local，关闭非远程来源策略并清空下次检查时间。身份、成员、对象摘要、预设和绑定保留。读取时的兼容结果在后续正常事务中保存，不迁移或删除实体文件。
已有远程包默认保留原整包范围；过去已经入库的未选成员不会自动删除。后续 Git 导入仅增加本次所选的新成员。
