# 来源与更新规则

| 来源 | 内容获取 | 更新与分发 |
| --- | --- | --- |
| 远程 Git | 受管缓存固定提交，保留完整共享结构 | 手动检查或定时更新；仅所选成员入库，整包订阅允许新增成员 |
| 网站安装 | 已支持站点适配器解析的仓库或版本下载源 | 具备来源标识时支持远程更新；仅保存网站名称、网址不会创建更新任务 |
| 本地文件夹 | 手动扫描并确认同步原目录 | 不推断 Git remote、不定时更新；确认同步后按预设纳新、排除和跟随规则分发 |
| 工具目录归集 | 归集与备份 | 不作为更新来源 |
| 旧本地引用 | 直接使用原实体 | 原目录内容自然变化，不生成更新任务 |

## 模块边界

- 更新中心、Skill 列表更新标记、侧栏数量、状态栏检查和任务统计使用相同远程更新条件。
- 本地文件夹通过预设中的文件夹扫描流程确认同步；更新中心提供入口提示，不再展示为定时任务。
- 后端拒绝为本地来源开启 notify/auto；CLI 的显式本地检查/同步仍可手动调用，调度器始终排除本地来源。
- GitHub 与 GitLab（含自建、子群组）支持仓库子目录网页链接；带斜线分支可显式填写分支。
- Git 单成员、部分成员与集合共用快照模型。未选成员不入库；整包订阅可纳新，已排除路径保留；固定目标、未应用预设的目标不跟随。
- 删除、改名保留原安装并待审阅；同名分发冲突不覆盖外部文件。
- 移除更新管理保留来源追溯和所有实体、预设、分发关系；后台与手动远程更新一并停止。

## 无引用同步包成员的清理

- 从预设移除或取消分发不会自动删除库中的旧版本；更新提示中的“保留”指库记录，不代表仍安装到工具。
- 已被所有所属同步包标记为上游缺失，或其来源已明确「移除更新管理」的成员，没有工具、本地来源或预设/包订阅选择引用时，可通过 Skill 库「从库中卸载」清理。仅关闭自动更新（策略为 off）不解除同步包成员保护；未移除更新管理的正常成员保持保护。
- 卸载在同一事务中清理包成员、缺失成员与订阅排除 ID，并按来源相对路径保留包级排除规则；以后上游恢复同路径时不会被自动重新加入。其他成员与来源更新管理保持。
- 卸载后重新检查该来源，更新中心按当前库记录重算提示。操作沿用统一库事务与既有实体保留规则，不直接删除用户原始源码目录。

隔离回归使用本机临时 Git 仓库，覆盖上游删除 → 从预设移除 → 库卸载 → 重新检查消除提示、上游恢复后的自动更新排除，以及工具/预设引用和其他同步包仍存在时的拒绝与回滚。修复前用例复现“成员仍属于同步包，请在包中处理成员变更”；修复后 3 项新增回归及核心库全部 136 项测试通过，Rust 格式与 diff 检查通过；未操作真实用户资料库。

2026-10-27：隔离 CLI 先复现移除更新管理后仍无法卸载，再验证 9 项场景：显式移除管理后无引用成员可卸载、解除分发后可卸载、关联清理及原文件保留；仅关闭策略、来源缺失、本地来源成员、分发、预设与包订阅选择仍保护。CLI 编译、核心库既有 136 项测试、Rust 格式与 diff 检查通过，独立代码审查通过；未操作真实用户资料库或替换已安装应用。

## 删除与状态读取性能

- 历史事务的恢复检查、引用检查及回收报告共用内存摘要索引。每次仍重新列目录并检查文件元数据，只有新增或变化的事务重新读取、解析；删除的文件会移出缓存。Engine 的克隆共享该索引。
- 摘要只保存检查所需字段，不常驻完整历史状态或回收文件清单。文件大小、修改/创建时间变化使缓存失效，Unix 额外检查设备、inode 和 ctime。读取期间文件变化或解析失败时拒绝本次操作，不回退到旧缓存。
- 磁盘事务格式不变。真正恢复和执行回收仍读取完整日志；未完成事务、归集备份、预设锁和外部软链保护继续执行，文件系统引用检查不使用缓存结果。
- 2026-10-27 隔离对照：优化前后均为 release 构建；复制并重定位 231 份历史事务（约 150 MiB），各执行 3 次删除。优化前 3.16–7.29 秒，优化后 0.155–0.199 秒，均完成删除及实体回收，保留原始源码。删除测量期间另有桌面编译负载，结果用于本机对照，不承诺所有来源达到相同时延。构建结束后只读复测真实库，重复状态读取中位数从 1.137 秒降至 0.035 秒，首次读取从 1.352 秒降至 0.186 秒；真实库摘要保持不变。
- 7 项隔离检查覆盖新增待恢复事务、旧预设缺省 locks、原子替换、同大小同 mtime 的原地变化、损坏记录、删除记录及迁移资料库；每次请求使用 Engine 克隆。136 项既有核心回归通过，其中一次锁冲突对应分组经隔离重跑通过；独立代码审查、前端类型/生产构建、Rust 格式及 diff 检查通过。

## 每天固定时间

- 更新中心「来源与计划 → 设置时间」支持按间隔或每天固定时间（HH:mm）；策略仍可选关闭、仅检查提醒、自动更新入库。
- 每天时间按本机时区计算，保存后显示下次检查时间。检查成功、失败或手动检查后，均重新计算下次计划；关闭策略清空下次检查时间。
- 桌面调度器每 60 秒检查到期来源；完全退出时停止，重新启动后补检查到期计划，不逐天补跑。夏令时跳过的时刻顺延到首个有效分钟，重复时刻只采用第一次。
- 旧配置未设置 `dailyTime` 时继续按 `intervalHours` 执行。切回间隔模式清除 `dailyTime`。

## 旧数据兼容

读取旧状态时，将关联本地包、原先由 .git 推断成 Git 的来源还原为 local，关闭非远程来源策略并清空下次检查时间。身份、成员、对象摘要、预设和绑定保留。读取时的兼容结果在后续正常事务中保存，不迁移或删除实体文件。
已有远程包默认保留原整包范围；过去已经入库的未选成员不会自动删除。后续 Git 导入仅增加本次所选的新成员。
