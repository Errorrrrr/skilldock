# 统一管理优化说明（2026-09-25）

本文记录本轮已落地的代码行为。目标是让本地、Git 和网站内容统一收录，再通过软链分发；工具目录中的现有内容通过归集预览接管，工作流包保留共享资源。代码变更不等于已发布版本，也没有自动迁移用户的真实资料库。

优化前的依据保留在[功能检查报告](functional-audit-2026-09-25.md)与[目标差距分析](management-scope-and-simplification-2026-09-25.md)。当前行为以本文和实际实现为准。

## 本轮实现范围

| 目标 | 本轮行为 | 保留边界 |
| --- | --- | --- |
| 本地内容进入统一目录 | 新本地来源复制完整内容入库，原路径作为手动同步来源 | 旧引用须明确确认迁入，不自动改造已有用户库 |
| 归集工具中的已有 Skill | 预览现有库与本批扫描的相同内容、同名冲突，确认后执行 | 旧 `import_folder` / `import_batch` 兼容接口仍存在，不等同于新预览流程 |
| 支持工作流包及散装 Skill | 提供整包与独立成员两种归集模式 | 不自动推断所有脚本和文档中的跨目录依赖 |
| 重名处理一致 | 库内可独立保留；同一工具按声明名检查，只选择一个实现 | 不自动修改 `SKILL.md` 声明名，不静默处理历史冲突 |
| 减少长期归集副本 | 新库默认长期留存 0 批，成功事务后清理临时原件 | 异常恢复材料、旧库设置、每来源一次更新撤销仍保留 |
| 操作结果可信 | 安装分阶段显示，失败可重试；预设保存与目标同步分别确认 | 网站安装会话在当前应用进程内保留，不跨重启恢复 |
| 统一目录可读 | 保留名称入口及完整包结构 | 未重构物理实体为可读包名目录 |

## 本地来源：复制入库与旧引用迁入

Skill 库和发现页的本地添加入口统一进入「本地来源」的添加弹窗。扫描返回成员、同名提示、资料库修订与内容摘要；确认后保存为 `local_managed`，成员不再以 `externalPath` 指向原目录。实体使用统一库当前内容快照，原文件夹保留，包内共享文件及相对路径保留。

再次同步需要重新扫描并确认。提交会检查 `revision`、预览时的 `contentDigest` 和复制结果；内容在确认前或复制期间变化，会拒绝执行旧预览。已登记来源不能在编辑时随意换路径，移动来源须另行添加并整理分发关系。

同目录重复添加复用来源。不同来源的同名内容若包摘要或成员路径不同，需要明确选择独立保留；内容合并时同步重映射来源成员 ID，避免后续整体分发引用已合并掉的记录。

同步时更新当前内容和已有受管链接：该来源新增、取消的成员按来源引用处理；同一成员仍被手动分发或预设引用时，保留这些引用并同步当前内容。原目录中已缺失的旧成员保留最后入库副本供整理。取消分发和移除配置直接处理已有来源引用，不因来源成员记录失配而提前失效；实际链接与所有权仍需校验。

旧 `local_reference` 不会因启动新版而自动迁移。来源列表保留旧引用标记，使用「迁入统一库」并确认复制及链接切换后才转为 `local_managed`。迁入保留原目录，此后原目录修改需要手动同步。以下情况会明确阻止迁入：

- 资料库尚未切换到单份当前内容模式。
- 成员仍由多个旧引用共享，无法只迁移其中一处。
- 旧成员在原目录缺失，无法完整复制。
- 原链接、目标、内容或引用关系不符合当前校验。

来源目录不可与统一库互相包含，也不能直接使用工具分发目录；归集工具已有安装仍使用独立的归集向导。

## 归集预览与包边界

归集从 `preview_collection` 生成审阅结果，执行使用 `collect_skills`。预览会与现有库及本次其他扫描成员比较声明名、完整内容摘要和包内相对路径。

| 模式 | 保存边界 | 适用情况 |
| --- | --- | --- |
| `package`，界面「保留整包结构」 | 保存扫描根的完整可收录内容，保留共享资源和原始相对路径 | 多 Skill 共同依赖包根文件、脚本或兄弟目录；默认模式 |
| `individual`，界面「各 Skill 相互独立」 | 每个独立 Skill 目录作为内容边界；父 Skill 及嵌套成员保持一起 | 已确认各成员不依赖扫描根或兄弟目录的散装工具安装 |

独立模式可以避免「工具甲有 A+B、工具乙有 A+C，导致两份相同 A 不能复用」的扫描根影响，但必须由用户确认依赖边界。仅比较 `SKILL.md` 文本不足以证明内容可复用。

预览结果使用以下状态：

- `new`：新增内容。
- `same`：完整内容与成员路径一致，可复用已有记录或本批其他成员。
- `conflict`：声明同名，但内容或包边界不同；须选择独立保留或跳过。
- 其他已有扫描状态，如软链、断链和外部管理：展示说明，不允许按普通实体接管。

执行时在事务中重新检查 `expectedRevision` 并重新生成内容指纹。指纹绑定扫描根、模式、是否接管、成员和内容摘要；来源内容、扫描范围或相关资料库状态改变时，要求重新扫描。复制后再次检查摘要，避免确认内容与实际入库内容不一致。

接管父 Skill 会影响父目录内的所有内容，因此不能选择父成员却跳过其中被连带接管的嵌套成员。可以一起审阅选择，或改为仅复制入库。交叉的文件事务路径会被拒绝。

## 重名：库内候选与目标启用分别处理

库内名称后缀用于区分记录，不会改动来源目录名或 `SKILL.md` 的声明名。分发计划读取实际声明名，按不区分大小写的名称检查：

- 一次给同一目标选择多个同名实现，预览报错。
- 同一目标已安装另一个同名受管实现时，进入既有来源切换规则，保留明确确认与引用保护。
- 更新内容改变声明名、将导致同一目标出现新的同名冲突时，提交前拒绝，不先改链接。
- 历史上已存在的冲突不会让取消分发和修复操作永久失效，也不会被自动删除。

未知文件、实体目录和异常链接仍受原有目标路径检查保护。系统不保证遍历所有 Agent 的外部插件或内部加载机制；软链分发成功也不等于 Agent 已加载成功。

## 网站安装与预设同步

网站安装后通过主来源 `sourceId` 与合并来源 `skillOrigins` 解析最终成员 ID。来源包含多个 Skill 时，所选预设及分发目标处理全部成员；找不到成员会明确保留失败状态，不再静默跳过后续操作。

安装分别记录入库、成员解析、每个预设和每个目标的状态。一个预设失败不会被随后分发成功覆盖；全部成功才自动关闭弹窗。已完成步骤在重试时跳过，不反复下载或重装。可关闭弹窗、去其他页面修复冲突，再回到发现页继续；重启应用后不会恢复这份前端会话。

加入预设使用 `syncApplied: true`，保留包订阅字段，并检查 `presetApplications` 的错误及已应用修订。成员保存成功但目标同步失败时，显示「成员已保存，目标同步未完成」；重试只做同步。Skill 库的加入预设入口使用相同规则。

重试前后会核验原请求成员：如果用户已经删除入库 Skill、从预设移除成员或删除工具目标，显示当前变化，不把用户的新编辑自动覆盖回旧选择。之前成功的预设阶段也会重新核验。可选择「结束本次操作」清除进度，已经入库、加入预设和分发的内容保留。

## 归集留存、事务恢复与更新撤销

这三类恢复用途独立，不能只用一个「有无备份」开关概括。

| 类型 | 本轮策略 | 作用 |
| --- | --- | --- |
| 归集成功后的原目录长期留存 | 新库 `backupRetention=0`；旧库沿用现有值，可设置 0–100 | 可选恢复到归集时的原目录版本 |
| 事务临时原件和日志 | 始终保留到安全提交，异常时保留待恢复材料 | 处理复制、建链失败或应用中断 |
| 每来源一次更新前内容 | 保留原有机制，与归集留存数量无关 | 撤销上次内容更新，而不是恢复归集前目录 |

原实体仍先临时改名为同目录下 `.skilldock-backup-<ID>`，再创建和校验软链。设为 0 时，在事务提交后清理可安全删除的原件。外部修改、内容校验失败或未完成事务会阻止清理并留下原因，不为满足「零留存」强删恢复材料。

「任务与记录」中的界面名称调整为「恢复与清理」。修改留存数量并保存，会立即清理超额的可删除原件；从旧值改为 0 也适用。旧库设置不会因升级被自动改为 0。

每来源的一次更新撤销仍使用现有当前内容恢复机制；撤销以来源包为单位，恢复相关内容和受管链接，并暂停自动应用。上述功能都不是异盘灾备，无法替代用户自行备份整个资料库。

## 接口

桌面与 `skilldock exec` 共用 Rust 核心。路径、ID、修订与摘要均使用实际预览结果；不要自行构造或复用过期确认参数。

| 接口 | 输入要点 | 输出或约束 |
| --- | --- | --- |
| `preview_local_source` | `path`，编辑时可传 `sourceId` | 返回 `root`、`revision`、`contentDigest`、成员及 `sameName` 提示 |
| `save_local_source` | `name`、`path`、`selectedPaths`、`revision`、`contentDigest`；可传 `sourceId`、`keepConflicts`、`migrate` | 返回 `snapshot` 与 `sourceId`；旧引用迁入必须显式 `migrate=true` |
| `preview_collection` | `paths`、`mode: package\|individual`、`adopt` | 返回规范化 `paths`、`mode`、`revision`、`fingerprint`、`items`、`warnings` |
| `collect_skills` | 预览的 `paths`、`mode`、相同 `adopt`，`expectedRevision`、`fingerprint`、`selectedPaths`、`resolutions` | 同名冲突路径需 `resolutions[path]="keep"`；跳过项不放入 `selectedPaths`；返回新快照 |
| `save_preset` | 原成员与包订阅字段，加 `syncApplied:true` | 返回快照仍需检查该预设的 `presetApplications`，接口成功不代表所有跟随目标都已同步 |
| `retry_preset_sync` | 无新增参数 | 尝试同步跟随目标，仍需读取目标错误及已应用修订 |
| `settings` | `backupRetention: 0..100` 的整数 | 保存后执行可安全完成的超额原目录清理 |

`import_folder`、`import_batch` 和旧本地引用数据继续兼容。新本地添加与新归集界面不再直接调用旧文件夹导入路径。核心 `import_preset_folder` 的历史 `reference` 参数仍属于兼容能力，不是普通添加流程。

## 未实施与后续边界

- 没有把 `.skilldock/objects/<摘要>/tree/` 重构成按可读包名存放的目录；外层名称软链仍是浏览入口。
- 没有执行真实用户库迁移、清理历史备份或发布安装包；用户须在应用中主动执行对应操作。
- 没有移除所有旧版本及旧来源兼容代码；没有把长期归集原件恢复界面彻底删除。
- 没有新增工作流执行引擎、跨目录依赖自动证明、文件级更新差异审阅或缓存定时清理。
- 默认不长期保存归集原件后，成功归集的历史原目录无法靠该副本撤销；提供「把当前内容还原为普通目录」仍是后续独立功能。
- 真实平台行为应按验证记录判断，不能由前端演示或静态检查推断 Windows/Linux 已完成验收。
