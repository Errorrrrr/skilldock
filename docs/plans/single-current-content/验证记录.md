## 隔离文件场景

- 连续三次来源更新：一份当前内容、一份最近恢复备份，两个工具及名称入口同步；撤销后回到一份，预设不保留内容锁。
- 同名相同完整包重复导入：复用记录与对象，返回有效的现存 ID，记录收录来源。对已经自动加后缀的独立内容重复导入也复用。
- 不同内容明确替换：保留原 Skill 身份和名称、合并管理工具及预设；撤销恢复原内容和原来源。
- 来源包包含共享依赖和新增成员：撤销恢复旧依赖，撤销新增成员的分发和引用。
- 旧库同名冲突未选择则拒绝；确认后所有目标统一。仅接管与旧记录完全匹配的名称及 name@version 链接，整理为公开名称目录与隐藏管理目录。
- 目标链接被外部替换时更新拒绝，其他工具和外部内容均不被覆盖。
- 删除目标期间连续更新：实际旧链接仍保护旧对象；重新添加通过历史绑定身份及完整内容校验自动绑定并切换当前内容。

## 迁移修复整理（2026-09-28）

### 保留的行为与边界

- 分发链接被实体目录替换时，预览具体路径及完整摘要；确认后事务备份再修复，失败回滚。普通文件占位、内容变化及包完整性异常仍拒绝。
- 所选快照按包预检并允许明确重新收录；缺失入口禁止重新收录。实际迁移重新校验全部选中内容，包括未分发成员。明确舍弃的副本不阻塞，重新检查保留有效选择。
- Git 来源批量选择只填充未选择且唯一的候选，不拉取远端、不覆盖手动决定。
- 历史入口仅按名称和确切目标接管；已登记且非活动的保留对象原样搬迁，迁移前后完整清单必须一致。活动及未知对象继续严格校验。
- 外部引用只豁免本次确实迁移的受管链接及经过这些链接的精确链条；直接未管理旧库引用仍拒绝并报告路径。相对链接原文保存在事务中供回滚使用。

### 摘要兼容

新内容摘要仅忽略普通 `.DS_Store` 文件及实际 `__pycache__`、`.pytest_cache`、`.ruff_cache`、`.mypy_cache` 子目录；独立字节码和其他普通文件继续计入。旧版仅忽略 Finder 文件的算法保留为校验回退，不重写既有对象 ID。完整树和备份清单不忽略缓存。
