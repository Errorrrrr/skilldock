# 单一当前内容接口

所有操作沿用 execute JSON action，失败返回明确错误且使用现有事务恢复；写请求必须提供 expectedRevision。

| action | 请求 | 响应与行为 |
| --- | --- | --- |
| preview_single_content | 无 | revision、alreadyEnabled、groups（name/skills/identical）、bindings、presets、backupCount、directoryRepairs、snapshotIssues。只读 |
| enable_single_content | expectedRevision、choices: [{name, skillId 或 keepSeparate:true}]、directoryRepairs | Snapshot；不同实体必须明确选择；相同完整快照成员自动复用；解除内容固定并统一管理绑定 |
| arrange_library | 无 | Snapshot；已为隐藏布局时幂等返回；旧布局通过有日志的存储迁移整理 |
| undo_content_update | sourceId、expectedRevision | Snapshot；恢复整个来源的上次内容，消费备份、暂停自动应用；新增成员同步撤销 |
| replace_current_content | skillId、replacementId、expectedRevision | Snapshot；将已导入的另一份内容作为当前内容，沿用原身份与名称，合并工具/预设引用并保留一次恢复；外部引用或完整性异常拒绝 |

Snapshot 新增 contentBackups（sourceId、createdAt、skills、addedSkillIds）、skillOrigins（Skill ID 到来源 ID 列表）、libraryEntries（Skill ID 到管理入口名）。新模式 schemaVersion=3；storageRoot 是内部 `.skilldock` 路径，日常目录为其父目录。

旧 set_follow、set_preset_follow、rollback、skill_history 在新模式拒绝，预设 locks 字段只作旧数据兼容，新模式清空。迁移/替换失败不能静默换用另一份内容。

## 分发目录修复（2026-09-23）

`directoryRepairs` 是预览时检测到的实体目录列表，每项为 `{bindingId, path, contentDigest}`。界面须展示目录及“先完整备份、再使用所选统一库内容”的行为；不同内容不会自动合并。确认迁移时原样提交该列表，没有实体目录时传空数组（旧调用可省略）。

执行时重新校验路径类型与完整目录摘要，摘要覆盖全部文件及资源链接，不忽略运行时文件。目录列表或内容发生变化、普通文件占位、来源完整性异常时停止。修复只针对已登记分发位置，原目录通过事务移到相邻隐藏备份，恢复入口位于任务记录的“归集备份”。失败时回滚；与统一库不同的备份受现有差异保护，不因保留批次超额而直接删除。该处理也覆盖分发版本没有变化但软链已变成实体目录的情况。

## Git 来源批量选择（2026-09-23）

迁移界面按 Git 来源 ID 提供批量选择，只填充尚未选择且该来源恰好有一个候选的冲突组。保留手动选择（含分别保留），多个仓库及同一来源内的多候选不推断优先级。选用的是已收录内容，不隐式拉取远端。仍通过原 choices 接口提交，实际迁移前可取消“仅显示未选择项”复核或调整全部选择。

## 重新收录后的旧入口兼容（2026-09-23）

旧模式重新收录内容后，名称入口可能仍指向旧对象。显式迁移同时用当前记录、现有分发绑定、已完成事务中同一 Skill ID 的历史记录核对 `name` / `name@version` 入口；只有名称和完整链接目标同时匹配才接管。实体目录、错误成员及未知链接仍拒绝覆盖。

整理目录时，当前 Skill、分发、预设锁和更新恢复备份仍要求快照摘要一致。已有完成事务证明其曾被登记、且不再被上述活动记录使用的保留对象，可以原样复制；其迁移前后完整文件清单摘要必须相同。不通过删除保留对象或放宽当前内容校验来绕过错误。未知损坏对象仍阻止迁移。

## 迁移前快照校验与重新收录（2026-09-23）

`snapshotIssues` 按当前来源包摘要去重，每项包含 `bundleDigest`、操作入口 `skillId`、全部受影响的 `skillIds` / `skillNames`、`sourceIds`、`path`、`reason` 和可为空的 `contentDigest`。缺少成员入口或无法计算当前内容摘要时，`contentDigest` 为 null，界面禁止重新收录并显示原因。

界面按所选成员筛选异常；尚未选择或分别保留时检查所有候选，明确舍弃的异常副本不阻塞迁移。重新收录沿用 `refresh_snapshot`，提交预览的 revision 和当前内容摘要，成功后重新预览并保留选择，不切换现有链接。“重新检查（保留选择）”用于处理预览过期，已消失的候选选择会被清除。

提交迁移时再次校验所有选中的受管来源包，包括没有分发或分发内容未变化的包；报错包含具体 Skill、来源包摘要和修复指引。预览通过不替代执行时校验。

## 目录迁移的保留链接检查（2026-09-23）

已移除目标路径仍参与迁移前引用扫描，重新添加同一路径不会直接豁免整个目录。仅当某个链接仍解析到登记的受管内容，且该分发位置会随迁移更新时，才视为已覆盖；其他链接若经精确的软链链条指向这个分发位置，也不会因最终仍解析到旧库而误报。外部间接链接原样保留。

受管相对链接按实际解析目标校验归属，事务记录原始链接文本，以便失败时恢复。未管理且直接指向旧库的链接、被改为其他成员的链接仍拒绝迁移，错误包含具体阻塞路径。对象永久清理继续扫描全部外部引用，不使用迁移豁免。
