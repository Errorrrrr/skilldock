# 单一当前内容技术方案

## 1. 需求背景
目录和副本管理目标见 [结构化需求](结构化需求.md)。现有对象保留规则把所有历史日志中的 Skill 都视为可回滚版本，目标和预设还可以分别固定内容。

## 2. 设计目标
保留完整来源包的依赖结构和文件事务能力，取消多版本产品语义。名称入口只指向当前实体；实体和管理文件由隐藏的内部目录保存。

## 3. 实现方案
### 3.1 整体设计
新增 single_content 模块集中处理单一内容约束、迁移、最近更新备份和撤销。新状态为 schemaVersion 3；schema 1/2 保持可读，通过明确预览迁移，旧客户端拒绝新状态。

- 每次事务提交前比较前后 Skill，按来源记录最近一次内容变化前的成员快照；未变化不轮换备份。
- 将管理绑定统一到对应 Skill 的当前内容，使用已有 Change 文件事务，完整性或链接验证失败则整个更新回滚。
- 预设锁作为旧格式兼容字段清空，分发使用当前成员；跟随标记统一开启，旧固定及任意历史回滚接口在新模式拒绝。
- 撤销以整个更新来源为边界，影响该来源所有受管目标。撤销成功消费备份，不产生历史版本链。
- 合并只针对完整快照摘要及成员路径相同的实体，保留来源追溯；不同内容由迁移选择或独立命名处理。
- 复用 cleanup_references、prepare_object_cleanup 和 run_object_cleanup；旧已完成事务不再保护所有历史快照，最近更新备份显式纳入引用集合。

### 3.2 总体流程
新建库 → 名称入口/内部存储 → 导入内容 → 分发到工具 → 来源预览更新 → 同步全部管理链接 → 保留一次备份 → 回收无引用旧对象。
旧库 → 预览冲突及工具影响 → 明确选用/独立保留 → 事务合并关系并解除固定版本 → 目录整理 → 引用校验后清理。

### 3.3 监控报警
独立本地应用无业务服务器监控。沿用应用任务记录呈现失败、待恢复和清理未完成状态；按用户指令不创建发布监听。

### 3.4 数据验证
隔离临时库核对：重复导入记录与对象数稳定；连续三次更新只保留当前及一次恢复对象；两工具和多预设始终指向同一当前实体；撤销恢复完整包依赖；异常链接阻止更新；迁移歧义不自动选；清理保护外部引用；旧数据可读新数据拒绝旧客户端。

## 4. 相关改动
| 模块 | 文件 | 类型 | 说明 |
| --- | --- | --- | --- |
| 核心 | single_content.rs、model.rs、lib.rs | 新增/修改 | 统一约束、恢复备份、事务接入及 schema |
| 分发/来源 | operations.rs、packages.rs、portable.rs | 修改 | 当前内容、取消锁定、迁移与导出 |
| 清理 | object_cleanup.rs | 修改 | 有界历史保留和自动回收 |
| 前端 | api/types、库/详情/预设/目标/设置 | 修改 | 当前内容展示、旧库迁移和撤销更新 |
| 发布 | package/Cargo/Tauri 版本 | 修改 | 同步新版本、标签触发 |
无数据库和外部服务新增，不增加依赖。接口契约见 [前端接口文档](前端接口文档.md)。

## 5. 风险评估
共享资源按包保留，不通过硬链接实现可变内容去重。未知外部引用只能通过已配置及历史扫描位置检测，无法证明安全的对象不自动删除。迁移确认前不改变工具固定状态。

## 6. 排期
依次交付核心约束、目录/迁移、界面、隔离验证、主分支及发布触发。

## 7. 上线方案
版本升级后旧库先展示迁移预览。编译、接口场景、恢复与清理验证通过才合入 main；同步版本字段后推送标签，不等待发布完成。

## 8. 其他相关信息
本方案替代 library-unification 中默认版本、多历史版本与预设锁定的未来设计；原草案仅保留背景，不作为本轮验收范围。
