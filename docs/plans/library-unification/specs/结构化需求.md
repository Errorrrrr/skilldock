# Skill 库身份与目录优化：结构化需求

> 2026-09-21 状态补充：本方案中的稳定身份、默认版本、迁移及回收设计仍待评审。当前已完成的同实体分发与版本展示见 [实体分发说明](../../../specs/entity-distribution.md)，重加目标自动绑定见 [目标绑定恢复](../../../specs/target-binding-recovery.md)。本草案不代表这些后续设计已经实现。

状态：方案草案；本次授权仅为制定方案，未授权执行数据合并、迁移或清理。

## 1. 问题

| 编号 | 用户看到的现象 | 当前根因 | 影响 |
| --- | --- | --- | --- |
| P1 | 同一个 Skill 显示多份来源，分发时难判断用哪份 | 名称用于前端分组；底层保留不同来源的记录，归集位置与更新来源混用 | 当前版本、更新归属与各工具所用副本不清晰 |
| P2 | 统一目录的 `objects` 下有许多哈希目录，内容似乎重复 | 按完整来源包的内容摘要保存版本快照，缺少面向用户的目录入口 | 难浏览、难解释占用空间，容易误删被引用版本 |

## 2. 目标与范围

- R1：每个确认后的逻辑 Skill 有稳定身份和明确默认版本，名称只负责展示；同名不直接等于同一个 Skill。
- R2：分别展示当前版本、更新源、历史收录位置及工具实际使用版本。
- R3：提供按 Skill 名称浏览的统一入口，内部对象继续支持完整包依赖、固定版本和回滚。
- R4：导入前识别重复/冲突；内容等价需核对运行依赖，不能只比较 `SKILL.md`。
- R5：把“合并展示”“整合记录”“切换工具版本”“回收对象”作为不同操作，独立预览影响。
- R6：迁移可恢复；来源身份、预设锁、借用链接、原始备份和未完成事务不丢失。
- R7：清楚区分可浏览对象、当前使用对象、历史保留对象和经核对可清理对象。

## 3. 推荐规则（待评审，不代表已确认实现）

- 相同已验证来源身份及成员路径，可自动识别为同一逻辑 Skill 的不同版本。
- 不同来源的同名内容只生成候选；无法证明完整依赖等价时保持独立。
- 每个逻辑 Skill 可有多个历史版本、多个收录位置；默认更新源最多一个，可为空。
- Git 包继续只获取一次，再按成员默认源关系更新；本地文件夹保持显式扫描同步，不转换为远程定时源。
- 默认版本只影响之后的新分发；改变已有工具的实际指向必须展示预览并由用户明确选择目标。
- 同名不同功能允许保留为独立 Skill，通过显示名或命名空间区分；不修改包内声明和现有安装目录名。
- 第一阶段不移动 `objects`、不删除实体、不改写现有工具链接。

## 4. 核心验收

1. 同一 Skill 的三个归集记录可统一查看，收录位置与唯一默认更新源分别展示。
2. 不同内容、共享依赖不同、外部引用无法核验时，不自动判为可安全合并。
3. 切换默认版本后，已有固定版本与受其他预设约束的工具仍指向原内容。
4. 从“打开 Skill 目录”进入可读入口，入口丢失可重建；入口不能被误识别为新的导入来源。
5. 迁移预览后发生任何相关状态、文件或链接变化，执行拒绝并提示重新预览。
6. 中断恢复和重复执行不增加重复记录、不删除外部目录、不破坏共享依赖。
7. 清理仅针对引用审计通过的对象，预览量不作为实际释放磁盘空间的承诺。

## 5. 不在本次方案实施首期范围

逐文件硬链接去重、自动推断任意脚本依赖、将所有包强制拆成独立 Skill、清空历史版本、自动切换现有安装、跨云服务同步。
