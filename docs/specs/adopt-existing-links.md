# 接管已有软链

用户目标：本地来源与工具中已有软链指向同一实体时，可选择由 SkillDock 负责后续取消分发时的链接删除。

## 交互

- 单个 Skill、预设、本地来源共用分发预览。默认显示“复用已有软链”，注明取消后保留。
- 预览存在可接管条目时，显示默认不勾选的“接管这 N 条已有软链的管理”。包括以前已经复用的同实体链接。
- 勾选后重新请求计划，逐项显示“接管软链管理”。用户点击“确认执行”后才生效；返回选择或重新打开时重置。
- 请求中禁用重复执行及选项；预览失败清空旧计划与接管选择，可重新预览；状态版本过期需要返回重新预览。
- 接管影响该链接的全部分发引用：有任一引用时保留，最后一个引用取消时删除软链，原始实体目录始终保留。

## 边界

- API plan/distribute/apply_preset/apply_local_source 增加默认 false 的 adoptExisting，不复用切换统一库版本的 takeover 授权。
- 仅允许目标入口为软链且解析到该本地 Skill 的实体。实体目录、同名不同源、父目录软链和失效链接仍拒绝覆盖。
- 执行在事务内重建计划并验证 revision。接管把已有相对软链规范为指向同一实体的绝对软链，记录 borrowed=false，不记录待恢复的 originalLink。
- 事务的 Change.before 校验原链接并支持失败回滚。旧 borrowed 数据无需迁移，可再次预览并选择接管。
- 本地来源重扫、包同步不会自动接管新增外部链接。现有切换版本操作仍在取消时恢复原链接。
